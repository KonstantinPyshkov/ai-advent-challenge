# День 2. Формат ответа

## Назначение

Один и тот же вопрос задаётся модели при разном уровне контроля формата:
без ограничений, с JSON-инструкцией, с лимитом `max_tokens`, со
`stop`-последовательностью, с JSON mode и с JSON Schema.

Цель — определить, какой способ контроля ломается и на каком этапе:
синтаксис JSON, соответствие схеме или правильность значений.

## Вопрос

Замоскворецкая линия Московского метрополитена: количество станций и
пересадки на другие линии метро. Учитываются только линии метро, без МЦК и
МЦД.

Эталон: 24 станции, 8 пересадочных станций. Обоснование — в
[дизайне эксперимента](docs/02-design.md).

## Модель и режим

| Параметр | Значение |
|---|---|
| Модель | `qwen3.5:35b-a3b` |
| Температура | 0.7 |
| `think` | `false` |
| Повторов на вариант | 3 |
| Всего прогонов | 18 |
| `num_ctx` | 8192 |

## Запуск

Из корня репозитория:

```bash
./scripts/run.sh day2
```

Проверка плана без запросов:

```bash
./scripts/run.sh day2 --dry-run
```

После прогонов в консоль выводится таблица «вариант × проверки» со средними
токенами и временем, а также краткий вывод: какой способ сломался и на чём.

## Артефакты

```text
logs/runs.json              все 18 прогонов: запросы, ответы, проверки, метрики
reports/report.md           сводка, таблица прогонов, примеры ответов
reports/report.csv          сводка для таблиц
conclusions/facts.md        метрики по вариантам
conclusions/conclusion.md   вывод по правилам, без участия LLM
```

Повторный запуск очищает `logs/`, `reports/` и `conclusions/`. Файлы
`data/`, `prompts/`, `docs/`, `config/` и `src/` не изменяются.

## Ограничения

- Локальная модель не имеет доступа в интернет: ответ строится по её
  знаниям, а не по актуальной странице метро.
- Ollama 0.40.15 не применяет `stop` в `/api/chat` для проверенных моделей.
  Параметр `stop` отправляется, но обрезка для варианта `stop` выполняется
  клиентом; это отмечено в отчёте.
- Проверка содержания отделена от проверки формата. Ошибки в названиях
  станций не означают, что сломался JSON.
