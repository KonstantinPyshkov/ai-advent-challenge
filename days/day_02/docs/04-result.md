## Что показали прогоны

- `baseline` не даёт JSON: 0 из 3 ответов разобраны. В этом прогоне
  обрезки не было, но технический потолок 8192 токена остаётся
  ограничением длины, а не форматным контролем.
- `format` даёт разбираемый JSON и соблюдает схему в 3 из 3 случаев.
  Поля при этом неверны во всех прогонах.
- `max_tokens=120` обрезает ответ во всех 3 прогонах; ни один ответ не
  разобран. Это самый дешёвый вариант по токенам (389), но он ломает JSON.
- `stop` обрывает JSON во всех 3 прогонах. Параметр `stop` отправлялся, но
  Ollama 0.40.15 не применила его в `/api/chat`; обрезка выполнена
  клиентом и отмечена в отчёте.
- `json_mode` даёт валидный JSON в 3 из 3, но схема не соблюдена ни разу:
  модель возвращает другую структуру.
- `schema` даёт валидный JSON и соответствие схеме в 3 из 3, но поля
  верны в 0 из 3: схема гарантирует форму, а не значения.

## Содержание

Ни в одном варианте количество станций и набор пересадок не совпали с
эталоном. Локальная модель без доступа в интернет ошиблась в фактах:
называла 14–20 станций и другие пересадки. Это ограничение знаний модели,
а не формата; для проверки содержания нужен внешний источник или
web-поиск, которого в ТЗ Дня 2 нет.

## Вывод

Инструкция в промпте — мягкий контроль: она может дать разбираемый JSON,
но не гарантирует структуру. `max_tokens` и `stop` ломают JSON при
недостаточном лимите или срабатывании разделителя. JSON mode гарантирует
только синтаксис. JSON Schema гарантирует форму, но не правильность
значений, поэтому её нужно дополнять проверкой содержания.
