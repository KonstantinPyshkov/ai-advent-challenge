# День 2. Дизайн эксперимента

## Гипотеза

1. Инструкция в промпте повышает вероятность разбираемого JSON, но не
   гарантирует ни синтаксис, ни структуру.
2. `max_tokens` обрезает ответ и разрушает JSON, если лимит меньше нужного
   объёма.
3. `stop`-последовательность обрывает структуру в месте срабатывания.
4. JSON mode гарантирует синтаксис JSON, но не соответствие схеме.
5. JSON Schema гарантирует форму, но не правильность значений.

## Вопрос

Замоскворецкая линия Московского метрополитена: сколько станций и какие
есть пересадки на другие линии метро. Учитываются только линии метро, без
МЦК и МЦД.

## Эталон

- линия: Замоскворецкая;
- станций: 24;
- пересадочных станций: 8.

## Варианты

| № | Вариант | Промпт | Ограничения |
|---|---|---|---|
| 1 | `baseline` | Вопрос | Нет форматных ограничений |
| 2 | `format` | Вопрос + JSON-инструкция | Текстовое описание формата |
| 3 | `max_tokens` | Вопрос + JSON-инструкция | `num_predict=120` |
| 4 | `stop` | Вопрос + JSON-инструкция | `stop=["}"]` |
| 5 | `json_mode` | Вопрос + просьба вернуть JSON | `format="json"` |
| 6 | `schema` | Вопрос + просьба вернуть JSON | `format=<JSON Schema>` |

Матрица: 6 вариантов × 3 повтора = 18 прогонов.

## Контроль переменных

- одна модель: `qwen3.5:35b-a3b`;
- одна температура: 0.7;
- `think=false`, `stream=false`;
- одинаковый системный промпт;
- одинаковый вопрос;
- одинаковый `num_ctx=8192`;
- для `max_tokens` меняется только `num_predict`;
- для `stop` меняется только stop-последовательность;
- для `json_mode` и `schema` меняется только режим форматирования.

## Метрики

- `json` — строгий разбор ответа как JSON;
- `schema` — соответствие JSON Schema;
- `fields` — совпадение количества станций и набора пересадок с эталоном;
- `truncated` — `doneReason == "length"`;
- `fenced` — ответ обёрнут в Markdown;
- токены, `requestMs`, полный сырой ответ.

Метрики формата и метрики содержания разделены: неверное название станции
не считается поломкой JSON.

## Ограничения

- Локальная модель не ходит в интернет; фактические ошибки — ограничение её
  знаний, а не формата.
- Ollama 0.40.15 не применяет `stop` в `/api/chat` для проверенных моделей.
  Параметр отправляется, но обрезка для варианта `stop` выполняется
  клиентом. Это зафиксировано в отчёте.
- Валидатор JSON Schema поддерживает используемое подмножество: `type`,
  `properties`, `required`, `additionalProperties`, `items`.
- Для `baseline` действует технический потолок генерации 8192 токена; в
  части прогонов он достигается. Это ограничение длины, а не форматный
  контроль.
- 35B выбрана как наиболее сильная локальная модель для фактического
  вопроса; 2B и 9B используются в Дне 5 для сравнения размеров.
