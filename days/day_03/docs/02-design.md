# День 3. Дизайн эксперимента

## Гипотеза

1. Пошаговая инструкция помогает на задачах, где нужен промежуточный вывод.
2. При включённом рассуждении часть выигрыша от пошаговой инструкции
   может исчезнуть, потому что модель уже строит цепочку рассуждений.
3. `prompt_then_solve` и `panel` увеличивают токены и время; их эффект
   нужно сравнивать с `direct` отдельно для каждого режима.
4. `think=true` повышает качество на задачах, где модель без рассуждения
   ошибается, но заметно увеличивает время.

## Задачи

| id | Тип | Проверка | Эталон |
|---|---|---|---|
| `arith-mult` | Арифметика | числовая | 391 |
| `logic-cats` | Логика | нормализованная | нет |
| `algo-sum` | Алгоритм | числовая | 10 |
| `date-2030` | Календарь | нормализованная | вторник |
| `data-avg` | Данные | числовая | 100 |

Ответ должен заканчиваться строкой `ОТВЕТ: <ответ>`. Проверка — точная
или числовая, без LLM-судьи.

## Способы

| Способ | Промпт | Вызовов |
|---|---|---|
| `direct` | Задача + маркер ответа | 1 |
| `step_by_step` | Задача + «решай пошагово» + маркер | 1 |
| `prompt_then_solve` | Составление промпта, затем решение по нему | 2 |
| `panel` | Один промпт с ролями аналитика, инженера, критика | 1 |

`panel` — один вызов: роли моделируются внутри одного ответа. Три
независимых агента дали бы другое соотношение токенов и времени.

## Рассуждение

DeepSeek `deepseek-flash` поддерживает управление мышлением:

- `off` — `thinking.type=disabled` (минимальное рассуждение);
- `on` — `thinking.type=enabled` и `reasoning_effort=high`.

В `prompt_then_solve` оба шага выполняются в одном режиме.

## Матрица

- 5 задач;
- 4 способа;
- 2 режима;
- 1 прогон на комбинацию;
- 40 прогонов;
- 50 API-вызовов (из-за двух шагов в `prompt_then_solve`).

Повторы не используются: ТЗ Дня 3 их не требует, а разброс температуры —
тема Дня 4.

## Параметры

- модель `DeepSeek-V4.1-Flash` (API id: `deepseek-flash`);
- `temperature=0`;
- `max_tokens=8192`;
- шаг составления промпта — `max_tokens=4096`;
- API: `https://api.deepseek.com`, ключ из `DEEPSEEK_API_KEY`;
- `stream=false`.

## Метрики

- `correct` — ответ совпал с эталоном;
- `answer` — найден маркер `ОТВЕТ:`;
- `avg токены` — среднее суммарное число токенов, для
  `prompt_then_solve` — сумма двух шагов;
- `avg время` — среднее суммарное время HTTP-вызовов;
- `truncated` — ответ оборван по лимиту.

## Сбои и ретраи

Пустой `content` не ретраится. Ответ сохраняется в журнале вместе с
`done_reason`, `prompt_eval_count`, `eval_count`, `num_ctx` и
`max_predict`, чтобы отличить:

- `output_limit` — модель израсходовала `maxPredict`;
- `context_overflow` — сумма prompt и completion достигла `numCtx`;
- `empty_content` — модель завершила ответ без финального текста;
- `truncated` — ответ оборван по длине, но текст есть;
- `timeout` / `http_error` — транспортные ошибки.

Технические сбои входят в знаменатель, но в отчёте показываются отдельно.

## Ограничения

- Модель не имеет доступа в интернет.
- `panel` — один вызов, а не независимые агенты.
- `prompt_then_solve` — два шага; токены и время суммируются.
- Пять задач дают малую выборку: разница в один ответ может быть шумом.
- Режимы `off/on` соответствуют отключённому и включённому thinking
  DeepSeek; `on` использует `reasoning_effort=high`.
