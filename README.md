# AI Advent Challenge

## О проекте

Репозиторий содержит решения учебного курса по практическому применению
больших языковых моделей. Каждый день курса оформляется отдельным каталогом,
в котором хранятся код, конфигурация, данные, промпты, документация,
журналы прогонов и результаты.

Проект представляет собой воспроизводимую локальную лабораторию, а не набор
разрозненных скриптов. Каждый запуск фиксируется в JSON-журнале, результаты
проверяются детерминированными правилами, а выводы формируются по
фактическим метрикам.

В текущей версии используется локальный Ollama. Архитектура предусматривает
подключение внешних моделей по ключу API, однако в заданиях первой версии
они не задействованы.

## Принципы

- **Каждый день курса оформляется отдельным каталогом.** В нём хранятся все
  материалы дня: код, конфигурация, данные, промпты, документация, журналы
  и результаты.
- **Общий код не дублируется.** Повторяющиеся компоненты выносятся в `core`.
  Конкретный день не содержит HTTP-клиента и логики запуска.
- **День не зависит от внутреннего устройства других дней.** `core` также
  не содержит знаний о конкретных заданиях; взаимодействие строится через
  общий контракт эксперимента.
- **Метрики отделены от служебных операций.** Время запроса измеряется
  только вокруг HTTP-вызова. Очистка каталогов, чтение конфигурации,
  проверки и формирование отчёта в это время не входят.
- **Ключи API не попадают в репозиторий.** Они хранятся только в переменных
  окружения или локальном файле, исключённом из git.
- **Финальная версия дня фиксируется коммитом и тегом `day-NN`.**

## Архитектура

Целевая структура проекта:

```text
core/        общий движок: клиент LLM, исполнитель прогонов, проверки, отчёты
cli/         единая точка входа для запуска экспериментов
days/        каталоги дней: код, данные, документация, журналы и результаты
config/      общие настройки и реестр моделей
docs/        архитектура проекта и зафиксированные решения
scripts/     скрипты сборки и запуска
```

`core` и `cli` будут добавлены начиная со Дня 2. День 1 реализован отдельным
модулем без общего движка: по условию требуется минимальный пример одного
запроса к модели.

Детали архитектуры: [docs/architecture.md](docs/architecture.md).

## Требования

- Java 21;
- Maven;
- [Ollama](https://ollama.com);
- локальные модели семейства Qwen3.5.

Используемые модели:

| Модель | Назначение |
|---|---|
| `qwen3.5:2b-mlx` | Быстрые проверки, День 1 |
| `qwen3.5:9b-mlx` | Эксперименты с приоритетом скорости |
| `qwen3.5:35b-a3b` | Задачи, требующие более высокой точности |

## Запуск

Сборка проекта:

```bash
mvn package
```

Запуск реализованного Дня 1:

```bash
./scripts/run.sh "Перечисли три преимущества локального запуска LLM."
```

Скрипт собирает соответствующий модуль и запускает его. Команды для
последующих дней будут указаны в README этих дней.

## Структура репозитория

```text
days/
  day_01/            минимальный запрос к Ollama
    config/          настройки дня
    docs/            техническое задание, порядок запуска, результат
    prompts/         промпты
    logs/            JSON-журналы прогонов
    src/             исходный код
    pom.xml
docs/
  architecture.md    устройство проекта
  decisions.md       зафиксированные решения
scripts/
  run.sh             сборка и запуск
  run.cmd            запуск в Windows
```

По мере добавления дней структура будет расширяться: в каталоге дня появятся
данные, отчёты, выводы и журналы автопроверок.

## Журналы и метрики

Каждый запуск сохраняет JSON-журнал в каталоге дня. В журнале фиксируются:

- параметры запроса;
- сообщения, отправленные модели;
- ответ модели;
- количество токенов;
- время HTTP-вызова, серверное время и время загрузки модели;
- статус выполнения и текст ошибки.

Перед повторным запуском удаляются только сгенерированные артефакты;
исходный код, документация, данные и промпты не изменяются.
