# Архитектура

## Идея

Проект — набор независимых экспериментов, по папке на день. Общий код
выносится в `core` только тогда, когда он действительно общий. День не
знает, как устроен другой день; `core` не знает, что такое «День 2».

```text
days/01-minimal/     — отдельный минимальный пример, без core
days/02-format/      — эксперимент, зависит от core
days/03-reasoning/   — эксперимент, зависит от core
days/04-temperature/ — эксперимент, зависит от core
days/05-models/      — эксперимент, зависит от core
core/                — исполнитель: клиент, runner, проверки, отчёты
cli/                 — одна точка входа: lab day2 / day3 / ...
```

`core` и `cli` появятся начиная со Дня 2. День 1 специально сделан
отдельным: по ТЗ это минимальный код, и он не должен тянуть за собой
лабораторию.

## Папка дня

Всё, что относится к дню, лежит в его папке:

```text
days/02-format/
├── README.md
├── docs/          # ТЗ, гипотеза, дизайн, runbook, результаты, вывод
├── config/        # настройки только этого дня
├── data/          # датасет, схемы, эталоны
├── prompts/       # промпты, включая промпт для автовывода
├── src/           # код эксперимента
├── logs/          # runs.json, analysis.json
├── reports/       # report.md, report.csv
└── conclusions/   # facts.md, ai.md, conclusion.md
```

День 1 использует сокращённый набор: `config/`, `docs/`, `prompts/`,
`logs/`, `src/`. Отчёта и выводов у него нет — это не эксперимент, а
проверка связи с моделью.

## Разделение ответственности

- **День** описывает: какие задачи, варианты, шаги, проверки и какой отчёт
  нужен.
- **Core** выполняет: очищает выходные папки, проверяет пустоту, делает
  прогрев, отправляет запросы, логирует, считает, рисует отчёт.
- **CLI** знает, какой день какой класс запускает.

День не делает HTTP. Core не знает конкретных дней.

## Метрики

Таймер включается непосредственно перед HTTP-запросом и выключается сразу
после получения тела ответа. Всё остальное — очистка, чтение данных,
проверки, отчёт, запись лога — в `requestMs` не входит и при
необходимости пишется отдельными полями.

## Запуск и перезапуск

При каждом запуске дня core удаляет только сгенерированные артефакты
(`logs/`, `reports/`, `conclusions/`), проверяет, что они пусты, и только
потом идёт запрос. Код, `docs/`, `data/`, `prompts/`, `config/` не
трогаются.

## Модели

Сейчас используется только локальный Ollama. На будущее закладывается
интерфейс `ChatModel`:

- `OllamaClient` — локальный вызов;
- `OpenAiCompatibleClient` — API по ключу.

Ключи хранятся только в переменных окружения или
`config/local.properties` (в `.gitignore`) и никогда не попадают в логи,
отчёты и git.

## Финал

День считается финальным после локального коммита и тега `day-NN`.
Черновики и промежуточные прогоны не коммитятся; повторный запуск дня
очищает его выходные папки.
