# Зафиксированные решения

## Стек и интерфейс

- Язык и система сборки: Java 21 + Maven.
- Интерфейс взаимодействия: CLI.
- Формат результатов: Markdown и CSV; реализован в Дне 2.
- Единая точка входа: `./scripts/run.sh day1|day2`.

## Архитектура

- Общий код вынесен в `core`: клиент Ollama, runner, workspace, проверки,
  отчёт.
- `cli` содержит точку входа и запускает эксперименты через `core`.
- Каждый день оформлен отдельным Maven-модулем в `days/`.
- День 1 остаётся отдельным модулем без `core`.

## Модели

- Локальный провайдер: Ollama, нативный эндпоинт `/api/chat`.
- Облачные провайдеры архитектурно предусмотрены, но в текущих заданиях не
  используются.
- Для Дня 1 используется минимальная модель `qwen3.5:2b-mlx`.
- Для Дня 2 используется `qwen3.5:35b-a3b`: вопрос фактический, нужен запас
  знаний и устойчивость к вложенной схеме.
- Распределение моделей по дням: 1 — 2B, 2 — 35B, 3 — 35B, 4 — 9B,
  5 — 2B + 9B + 35B.

## Выполнение экспериментов

- Повторный запуск дня очищает только `logs/`, `reports/` и `conclusions/`.
- Метрики времени рассчитываются только вокруг HTTP-запроса.
- Журналы и отчёты хранятся в каталоге дня.
- Ключи API размещаются только в переменных окружения или
  `config/local.properties` и не попадают в git.
- Вывод Дня 2 формируется по правилам, без отдельного AI-нарратива.
- Ollama 0.40.15 не применяет `stop` в `/api/chat`; параметр отправляется,
  а обрезка для варианта `stop` выполняется клиентом. Ограничение отмечено
  в отчёте.
- Финальная версия дня фиксируется локальным коммитом и тегом `day-NN`.
- Отправка изменений в удалённый репозиторий (push) не выполняется.
